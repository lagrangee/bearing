# Project Orientation

## Applicability

Use after an explicit Active-project Orientation request or acceptance of the Fresh post-Configure
offer.

## Authority

Orientation is a read-only Agent synthesis. It may draft Project Summary, Roadmap horizons, and
ordered Gate candidates. It writes nothing and grants no later owner authority.

## Operation

1. Read current Project Context and Project inspection first. Deepen only the named Roadmap, Gate,
   Effort, or native references needed for the requested orientation. Read implementation or run
   validation only when the Human asks for technical evidence.
2. When existing-work evidence is included, consume the bounded Scope Review view in the same
   visible operation. If the user explicitly omits it, state that the Orientation is limited.
   Offer a visibly higher-cost provider traversal only when the bounded view cannot answer a
   material question.
3. Keep repository facts, native-work facts, canonical planning facts, Agent inference, evidence
   limitations, and unresolved questions distinct.
4. Return only the requested orientation: current understanding and boundaries, accepted planning
   state, and Next Work judgment when asked. Draft new Summary or horizon candidates only when the
   Human asks to create or reconsider planning. Discard any transient native inventory at close.

## Completion criterion

Orientation used the explicit native-evidence depth, separated evidence classes, answered only the
requested orientation, wrote nothing, and left every candidate to later explicit acceptance through
its owner.
