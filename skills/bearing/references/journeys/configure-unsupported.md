# Unsupported Configuration

## Applicability

Use when Configure Inspect reports Invalid or Unsupported Preview state.

## Authority

Bearing may explain the incompatibility and, only when the Human chooses it, coordinate an explicit
reviewed platform removal. It does not migrate, repair, purge, or reinterpret unsupported bytes.

## Operation

1. Stop before the requested operation and report the typed unsupported facts, preserved data
   boundary, and why the current runtime cannot continue. Do not use direct repository reads to
   continue the rejected operation or produce a degraded result. Completion: incompatibility is
   concrete and the requested operation did not start.
2. Stop with the unsupported repository preserved. If the Human explicitly chooses removal,
   prepare an external, exact, Agent-reviewed removal proposal and obtain separate authority before
   any removal. Completion: the unsupported operation stops, or removal is separately accepted.
3. After reviewed removal validates, report the new Fresh lifecycle. Fresh Configuration is a
   distinct operation with its own choices and final review. Completion: activation can begin only
   from a clean supported state.

## After this operation

- **Required:** Validate removal before any Fresh plan.
- **Do not infer:** Unsupported state never authorizes migration, silent repair, broad deletion, or
  automatic Fresh activation.

## Completion criterion

Unsupported state either remained untouched or completed one explicitly authorized reviewed
removal and returned to a separate Fresh workflow.
