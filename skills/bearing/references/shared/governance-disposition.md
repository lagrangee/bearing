# Governance Disposition

Load this shared protocol only after a Bearing-activated request completes native Work Management handling, or when the user accepts the one optional successful Fresh Setup review or explicitly requests a later Active-project Bearing Scope Review. It gives rationality advice without becoming a planning, enrollment, discovery, or persistence owner.

## Scope Review

For a requested review, ask for one transient Work Management inventory bounded to the current conversation. Compare it with explicit canonical commitments and accepted Work Bindings only. Repository presence, tracker membership, labels, textual similarity, recent activity, and provider discovery are not enrollment authority. Discard the inventory when the review finishes.

Never run ambient discovery, background inventory, automatic enrollment, or standalone-work governance. A Fresh Setup may offer the review once after complete success. An Active project runs it only when the user explicitly requests it. Declining or ending the review changes nothing.

## Request Disposition

After native handling, return exactly one transient Governance Disposition:

- `already managed`: the request is inside one explicit accepted commitment or Work Binding.
- `enrollment suggested`: at most one high-confidence existing Effort or planning target has a material governance relationship to the request. Name that candidate and explain the relationship without implying acceptance.
- `kept standalone`: no reasonable binding exists, the evidence is insufficient, or the work is intentionally outside Bearing Scope. State plainly that Bearing does not govern this work.

Do not infer a candidate from native kind, labels, title words, repository proximity, or the desire to make the project look complete. When there is no reasonable binding, use `kept standalone`; do not manufacture a formal suggestion.

## Enrollment Boundary

A disposition never creates or changes a Work Binding. `enrollment suggested` is advice awaiting explicit user acceptance. Only after that acceptance may the correct planning owner inspect the full relation and present its own exact write set. Binding to an existing Effort is owned by Alignment Check; creating a new Effort begins with Effort Lifecycle and then uses Alignment Check for the accepted Work Binding. Work Management and Execution remain free to create, triage, implement, and resolve standalone work without Bearing involvement.

## Persistence Boundary

This protocol never writes the transient inventory or disposition to Project Snapshot, Portal, Attention, Map, Project Brief, Project Summary, provider observations, discovery selections, canonical history, native work, or local tracker history. It returns conversation output only. Targeted Native Reconciliation remains required for exact refs after a successful transaction inside an already accepted Work Binding; it never enrolls a standalone request.

## Outcome

Report the Work Management outcome without translation, followed by exactly one disposition and its evidence boundary. If inventory or relation evidence is insufficient, return `kept standalone` rather than blocking valid standalone handling. Completion means the inventory is discarded, no scope mutation occurred, and any proposed enrollment is still awaiting its planning owner and explicit user acceptance.
