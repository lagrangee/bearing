# Planning Transaction

Use this shared contract for an internal branch write.

Read current canonical sources and declared relations before proposing a change. Authored prose is not a substitute for typed identity or relation fields. Keep native work lifecycle and canonical Bearing mutation ownership separate.

Normalized Semantic Text is non-blank plain UTF-8 without Markdown or HTML links, code spans, emphasis, block quotes, code blocks, comments, headings, lists, or other formatting syntax. Keep schema keys, IDs, commands, fingerprints, structural references, and record delimiters outside that rule.

Before acceptance, present the semantic effect, exact owner, exact write set, dependent reference changes, and preserved data. Never treat test success, derived readiness, or generated evidence as human acceptance.

Immediately before mutation, re-read every input and target precondition. Validate the complete virtual result before the first write. Apply the accepted owner-scoped set atomically; on failure restore previous bytes and remove only transaction-created files or directories. Report any external or post-commit owner stage separately instead of rolling it into a false repository failure.

After a successful canonical change, run `$HOME/.bearing/bin/bearing sync --repo <repo-root>`, require zero structural diagnostics, and re-inspect any completeness-sensitive target. Source truth outranks disposable cache. User-visible proposals, decisions, outcomes, and newly authored human-reviewed artifacts follow the current user's language; schema keys, IDs, commands, and this agent-facing contract remain English.
